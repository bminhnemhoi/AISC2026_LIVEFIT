# Risks, kill/pivot criteria and adversarial self-review

Research date: **2026-10-05**. Repository: `rebuild/livelift-next`. This is research and a proposed product strategy, not implementation or proof of market demand. The [V3 master roadmap](../../roadmap/LIVELIFT_V3_MASTER_ROADMAP.md) governs future work; these reports supply evidence.

## Risk register

Likelihood/impact judgments are qualitative. No statistical probability or field demand was measured. Release blockers differ from business kill conditions: an API denial blocks enrichment, not a valuable manual workflow.

| ID | Risk | Likelihood / impact | Mitigation / evidence | Kill / block / pivot trigger |
|---|---|---|---|---|
| R1 | No useful gap on target TikTok account | High / fatal | Account walkthrough before build; keep native features | Equivalent anchored planning/adaptation is demonstrated natively |
| R2 | Opsique or configured rundown already sufficient | High / fatal | Fair template and accessible trial comparison | No meaningful reduction in recurring recovery/review burden |
| R3 | Manual capture adds workload / misses truth | High / core | One routine transition command; observe actual timestamps | After two iterations, capture burden/accuracy gates fail |
| R4 | Host View distracts or duplicates scripts | Medium / layer | Separate host glance/message test | Remove view if comprehension/delivery worsens |
| R5 | False-safe forecast from unknown remaining time | High / reliability | Explicit remaining estimate, lower bounds, minimum/anchor rules | Any demonstrated silent infeasible “safe” state blocks release |
| R6 | Learning infers sales causality or sparse patterns | High / trust | Operational language, sample count/spread, actual completed grouping | Any unsupported causal claim blocks release; sparse history disables rule |
| R7 | API entitlement/coverage/version not available in VN | High / enrichment | Read-only approved app probe; exact source binding | Drop enriched tier; do not kill a proven manual wedge |
| R8 | Phantom pin/promotion execution | High / trust | Explicit enums; report vs observation independent; no unsupported controls | Any false platform-confirmed/performed claim blocks release |
| R9 | Legacy auth/tenant/read boundaries reused unsafely | High / external deployment | Scoped auth and lookup isolation before external data/use | No external release while shared/open access remains |
| R10 | Data loss/ack ambiguity/reconnect split brain | High / backend | Atomic state/event/receipt; single authority; backup/restore | Any lost acknowledged command blocks backend/production gates |
| R11 | No repeat use or willingness to pay | High / business | Repeat-session pilot; concrete tradeoff/offer testing | No ≥3 teams voluntarily returning/applying useful changes; reassess before scaling |
| R12 | Multi-platform/agency scope swallows wedge | High / delivery | One room; portability only; choose one later bet | New scope lacks observed demand and logged approval |
| R13 | Weak novelty/demo misunderstood as generic timer | Medium / project | Show actual-to-next patch and fair comparative evidence | If only countdown matters, use template/integration; revise project claims |
| R14 | Clock/device/network studio reliability | High / use | Elapsed vs wall clock, stale status and real-device drills | Unnoticed stale host / wrong anchor / conflicting state blocks release |

## Decision tree

**Native/substitute equivalent?** Stop broad rebuild; specialize only a demonstrated missing job. **Manual capture/recovery fails twice?** Pivot to a template or review companion only if that job has evidence; otherwise stop. **Desk passes but Host View fails?** Remove the view. **Operational record passes but repeated adaptation unused?** Keep simpler execution product and remove learning emphasis. **API denied?** Offer manual only. **No recurring paid/use intent?** Do not scale multi-room or production scope to hide the failure.

Any critical cue miss, false success, lost acknowledged command or access leak blocks the applicable release regardless of preference/demo appeal. A small formative sample supports iteration decisions, not population superiority.

## Final adversarial self-review

These are desk critiques, not interviews with the named roles. The recommendation was revised in response to the following attacks.

| Perspective | Strongest attack | Revision / surviving condition |
|---|---|---|
| TikTok product manager | We already have scripts, sequence advice, moderators, replay and practice; why another screen? | Withdraw broad gap/AI/simulator claims; focus bounded future-plan recovery, require account check. |
| TikTok seller | I want more sales, not data entry. | Promise operational savings only; exclude solo/analytics-first cases and kill if capture burden exceeds savings. |
| Livestream host | A tablet can distract me and duplicate my script. | Host View P0.5 VALIDATE; concise cues; remove if host delivery worsens. |
| Livestream operator | I already manage this with a sheet; Start clicks may be another chore. | Use competent baseline, one routine command and accurate capture gate; no forced evidence forms. |
| Agency owner | I need many rooms, shifts and client reporting. | Choose small single-room recurring teams first; decline large-agency scope until retention evidence. |
| Broadcast rundown expert | Fixed anchors, over-under and presenter clocks are old. | Explicitly classify as commodity; compare Ontime/Shoflo/Rundown Studio; no scheduling-invention claim. |
| Startup founder | Low moat, expensive build, unproven willingness to pay. | Cheap paired validation first; three usable phases; template/review fallback and business kill criteria. |
| Competitor | Opsique advertises the whole loop; we can copy patches. | No first-in-market claim; hands-on comparison where accessible; defend only measured workflow fit/history. |
| Frontend engineer | Current pages bypass API and fixtures mismatch sessions. | One client/domain boundary, real IDs/not-found, persisted actual review; current tests do not certify those behaviors. |
| Backend engineer | Local listeners/open reads/shared token will not support teams. | Single-device phase boundary; atomic server receipts and scoped access before team/external use; restore gate. |
| Data scientist | Duration/GMV correlations and sparse samples cannot show causal lift. | Operational medians/sample counts, no causal revenue claims; experiments defer behind design/instrumentation. |
| AISC judge | This looks like an existing rundown tool with product names. | Show connected actual-to-next plan behavior and honest substitute evaluation; claim workflow contribution, not invented novelty or judging criteria. |

## What survives the attack

A **narrow but valuable hypothesis** survives: recurring operator-led teams may benefit from constrained execution recovery connected to real actual history and a coherent changed next plan. Global novelty and defensibility are modest. The product earns a build decision only through a fair native/sheet/rundown comparison and repeated use. No stronger verdict is justified from repository/source research alone.

## Claims still unresolved

Authenticated native feature coverage in target accounts, direct competitor usability/pricing, frequency/cost of timing incidents, host attention effects, willingness to pay, repeat adaptation use, approved VN API access and production reliability. Each is a gate, not a statement concealed as a fact.
