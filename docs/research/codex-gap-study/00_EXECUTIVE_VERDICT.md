LiveLift should pivot its emphasis from recommendations/analytics/causal sales optimization toward **manual commerce show execution and operational learning**. Stop expanding the current fixture UI until the wedge survives user comparison.

## The product worth testing

For recurring Vietnamese merchant teams and small agencies with a dedicated operator and host, replace manual recalculation and fragmented show notes. Keep TikTok LIVE Manager open for native operations. LiveLift owns the agreed plan, actual transitions, deadline risk, and next-session changes. It must create value before a TikTok authorization or AI model exists.

P0: manual Product Pack; timed segments and fixed anchors; NOW/NEXT with one concrete recovery reason; start/extend/skip/shorten/reorder with operator confirmation; minimal cue/action notes; Plan vs Actual; selected-change clone; deterministic offline rehearsal. Host View is **P0.5 — VALIDATE**, not a prerequisite for P0 or a claim of novelty.

## What changes from earlier research

| Earlier conclusion | Correction |
|---|---|
| TikTok lacks operational preparation and next-session advice | Native setup, product sets, AI lineup guidance and diagnosis already cover parts. The proposed gap is execution against a team-authored timing plan. |
| TikTok APIs are strictly post-LIVE | Minute endpoint is post-session. Creator analytics and seller daily LIVE overview exist; access and freshness remain untested. |
| Existing analytics adapter imports catalog | `src/livelift/ingest/tiktok_shop.py` has LIVE analytics, not catalog synchronization. |
| Legacy execute means the platform was pinned | The traced route writes local state and exposure; no external TikTok request occurs. |
| Current frontend implements durable realtime/offline/replay | Its pages use the fixture simulator; realtime and drafts are memory-local; some review records are shared fixtures. |
| Scientific core failed or is mathematically impossible in all small rooms | Historical power results concern different outcomes and assumptions. Preserve the research; defer it from the commercial P0. |
| Rundown, Host View, semantic replay are globally new | They are established patterns or combinations. Demonstrate this project's specific recovery and learning workflow without a first-in-market claim. |

## Investment decision and stopping rule

Run the paired validation in [14](14_USER_VALIDATION_PLAN.md) before the full backend rebuild. Proceed only if timing recovery and review/next-plan work improve without unacceptable capture burden. If spreadsheets or an existing rundown product tie LiveLift, integrate/configure that tool or narrow to operational review; do not add AI to hide a weak wedge.

The source crawl is complete for this bounded study. No authenticated seller account, private partner entitlement, live platform call, customer interview, or competitor trial was performed. Those remain explicit validation tasks. Missing documentation is not proof of absence.
