# Novelty and gap analysis

Research date: **2026-10-05**. Repository: `rebuild/livelift-next`. This is research and a proposed product strategy, not implementation or proof of market demand. The [V3 master roadmap](../../roadmap/LIVELIFT_V3_MASTER_ROADMAP.md) governs future work; these reports supply evidence.

## What TikTok does not currently solve — bounded finding

A team-owned **time-budgeted future commerce plan with explicit hard-anchor recovery and approved operational changes carried into the next rundown** was NOT FOUND in the reviewed official material. TikTok does solve much of the surrounding product preparation, sequence advice, host scripts, live actions, analytics, replay, diagnosis and practice. Absence from documentation is not absence from all accounts; verify on relevant VN accounts. See [the UI capability map](03_TIKTOK_COMPLETE_CAPABILITY_MAP.md).

## What LiveLift uniquely combines

The repository has unusually careful distinctions between plan, operator choice, attempt, report, provider observation, time known and later evidence, alongside scientific simulation/experiments and commerce session concepts. That combination is a useful foundation, but the current rebuild has not delivered the end-to-end product it implies. A plausible V3 contribution is to connect **commerce constraints + manual execution history + selected next-show adaptations**, with a faithful offline scenario and no required platform control.

“Unique in this repository” is defensible; “unique in the market” is not established. Opsique publicly combines commerce rundowns, host outputs and post-show operations. Professional rundown products already solve timing/cueing. [C1: Opsique platform](https://www.opsique.com/platform/); [C5: Shoflo changelog](https://feedback.shoflo.tv/changelog); [C9: Rundown Studio running a show](https://rundownstudio.app/docs/rundown/running-a-show/).

## Genuinely new, incremental, commodity

| Category | Finding | Claim discipline |
|---|---|---|
| Genuinely new algorithm / scientific result | None established by this study | Do not claim a new scheduling algorithm, causal estimator or first simulator. |
| Potential project innovation | A demonstrable closed operational loop preserving commerce commitments and the evidence behind chosen adaptations | Present it as a designed/evaluated workflow contribution, contingent on comparison results. |
| Incremental specialization | Promotion anchors, required product coverage, actual duration learning, minimum viable pitch time, manual external-action report | Valuable if they reduce recurring work; not patent/first-in-world claims. |
| Combination innovation | Plan → forecast → recovery → actual → approved next-plan patch, on one session identity | Combination may matter, but Opsique makes even the combination contested. |
| Commodity | Timers, NOW/NEXT, presenter screens, shared state, product lists, notes, CSV import, generic dashboards, AI scripts | Use existing patterns; don't base novelty argument on them. |
| Valuable engineering discipline | Missingness, provenance, immutable baseline, idempotency, no hindsight leakage | Necessary for trustworthy results; expose only when users need it. |

## What must not be claimed as novel

Do not claim first commerce Run of Show, first dynamic timeline, first Host View, first AI selling script, first simulator, first TikTok live recommendation, first product sequencing, first replay/comments synchronization, first causal/switchback software or first provider-neutral ledger. Do not treat unsupported automatic pinning as a differentiator. The evidence contradicts or fails to support those claims. ## A credible project innovation statement

> LiveLift explores a platform-independent operations workflow for recurring commerce shows: explicit timing and coverage constraints guide operator recovery, actual execution remains distinct from the plan, and approved operational lessons become changes in the next show. A deterministic rehearsal and paired substitute comparison test whether the workflow reduces recovery and review effort.

This is an original synthesis and evaluation target, not a copied vendor claim. For an AISC-style presentation, demonstrate working timing/record/patch behavior, publish the comparison protocol and limitations, and avoid invented judging requirements or award promises. A seeded simulation alone proves reproducibility, not seller benefit, sales lift or causal validity.

## Novelty kill test

Kill the broad novelty story if Opsique or a configured rundown tool already performs the same loop for the ICP with comparable burden. Kill the TikTok-gap story if relevant VN account workflows provide equivalent anchored planning/adaptation. Keep the operational wedge only if users repeatedly choose it and measurable coordination/recovery cost falls. Otherwise pivot to a commerce template/integration, a narrowly useful review tool, or stop.
